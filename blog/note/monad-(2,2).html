F(x) = 2 * x^2 上のモナドについて

多項式関手 F(x) = 2 * x^2 、Haskellで表現するならば

data F x = F Bool x x
  deriving Functor

という関手上に、どのようなMonadのインスタンスが定義できるだろうか？ それは同型で同一視できるものを除いていくつあるだろうか？という問題を考えました。

結論としては、そのようなMonadのインスタンスは同型を除いてちょうど3つあり、

  • Product (Writer Xor) Identity と同型なもの

    ただし

    data Product f g x = Pair (f x) (g x)
newtype Writer m x = Writer (m, x)
newtype Identity x = Identity x

xor :: Bool -> Bool -> Bool
xor = (/=)

newtype Xor = Xor Bool
instance Semigroup Xor where
  Xor a <> Xor b = Xor (a `xor` b)
instance Monoid Xor where
  mempty = Xor False

    です。WriterとProductのMonadインスタンスは(TODO:リンク)を参照してください。

  • Product (Writer Any) Identity と同型なもの

    (TODO:Anyのリンクor説明)

  • 以下のように定義されるインスタンスと同型なもの

    pure :: forall x. x -> F x
pure x = F False x x

join :: forall x. F (F x) -> F x
join (F a (F b0 x00 x01) (F b1 x10 x11)) =
  case a of
    False -> F b0   x00 x11
    True  -> F True x10 x11

となっています。この文書では、なぜそのように言えるのか ということを説明します。

記法の準備

いま考えているF上のMonadのインスタンスというものは、 以下のような形をしています。

pure x = F ? ? ?

join (F False (F False x0 x1) (F False x2 x3)) = F ? ? ?
join (F False (F False x0 x1) (F True  x2 x3)) = F ? ? ?
join (F False (F True  x0 x1) (F False x2 x3)) = F ? ? ?
-- などなど......

本記事の扱う内容で、F False ...などと記述していくのは冗長になってきます。 そこで、 記法を簡略化してF b x y = b[x,y]と書いてよいことにし、更にBool型の値もFalseを白丸◯、Trueを黒丸●で表すことにします。 上記の例にこの記法を使うと、

pure x = ?[?,?]

join $ ◯[ ◯[x0,x1], ◯[x2,x3] ] = ?[?,?]
join $ ◯[ ◯[x0,x1], ●[x2,x3] ] = ?[?,?]
join $ ◯[ ●[x0,x1], ◯[x2,x3] ] = ?[?,?]
join $ ◯[ ◯[x0,x1], ●[x2,x3] ] = ?[?,?]
-- などなど......

のようになり、見やすくなります。

“同型を除いて”のための正規化

先程、Monadインスタンスが”同型を除いて”3種類であると書きましたが、 “同型を除いて”をはっきりと定義しておきましょう。

まず、「モナドのインスタンス」とは、モナド則を満たすpureとjoinの組MonadInstance mのことであると定義しましょう。

data MonadInstance m = MonadInstance {
    pure_ :: forall a. a -> m a,
    join_ :: forall a. m (m a) -> m a
  }
-- ただし (pure_, join_) はモナド則
-- 
-- > join_ . pure_ = id
-- > join_ . fmap pure_ = id
-- > join_ . join_ = join_ . fmap join_
--
-- を満たす組に限る

同じFunctor mの上に定義されたインスタンスが2つあったとします。 それぞれdef1, def2と呼び、それらのpure_とjoin_もpure1, pure2などと番号を つけて区別しましょう。

def1, def2 :: MonadInstance m
def1 = MonadInstance { pure_ = pure1, join_ = join1 }
def2 = MonadInstance { pure_ = pure2, join_ = join2 }

自然変換 tr :: forall a. m a -> m a がdef1からdef2へのモナド同型であるとは、以下の2条件をどちらも満たすことです。

  1. tr は自然同型である。言い換えれば、逆自然変換tr' すなわち tr' :: forall a. m a -> m a であって tr' . tr = tr . tr' = id となるものが存在する。

  2. tr はモナド演算を保つ、すなわち

    1. tr . pure1 = pure2
    2. tr . join1 = join2 . fmap tr . tr

    が成り立つ。

def1とdef2が同型であるというのはdef1からdef2へのモナド同型が少なくとも1つ存在すること と定義します。この「同型である」という関係はMonadInstance m上に同値関係を定めます。

Monad Fとして考えられるインスタンスが同型を除いて3種類だというのは、 MonadInstance F の値を「同型である」という同値関係で分類すると、ちょうど3つの同値類に分けられること、という意味になります。

以降はそのことを示していくのですが、その際の方針として、 モナドのインスタンスの”正規型”を得る、というやり方をとります。 モナドのインスタンスのうち、ある条件を満たすものを第一正規型のインスタンス と定義し、次にどんなインスタンスも、ある第一正規型のインスタンスと同型であることを示します。 続けて、どんな第一正規型のインスタンスもある第二正規型のインスタンスと同型 どんな第二正規型のインスタンスもある第三正規型のインスタンスと同型、と繰り返します。

そのようにして定義した第三正規型という条件は、

  • どんなインスタンスもある第三正規型のインスタンスと同型
  • かつ、第三正規型のインスタンスの間の同型は「自明な同型」のみ、すなわちid :: forall a. m a -> m aによる自分自身への同型しか存在しない

となっています。そして、第三正規型のインスタンスで異なるものをすべて考えるとそれがちょうど3つであることをもって 「F上のモナドのインスタンスは同型を除いて3種類」であることを示します。

F上の自然同型

F上の自然同型forall a. F a -> F aにはどんな物があるのかを確認しましょう。 F上の自然同型は 2*2*2 = 8個存在し、それぞれ

  • コンストラクタ◯と●を入れ替えるか notF か、そのままにする id

    notF :: forall x. F x -> F x
notF b[x0,x1] = (not b)[x0,x1]

  • コンストラクタを変えずに、◯の2つの要素を入れ替える swap_◯ か、 そのままにする id

    swap_◯ :: forall x. F x -> F x
swap_◯ ◯[x0,x1] = ◯[x1,x0]
swap_◯ fx = fx

  • コンストラクタを変えずに、●の2つの要素を入れ替える swap_● か、 そのままにする id

    swap_● :: forall x. F x -> F x
swap_● ●[x0,x1] = ●[x1,x0]
swap_● fx = fx

をそれぞれ組み合わせた

(swap_◯ | id) . (swap_● | id) . (notF | id)

の合計8パターンで全て尽くされています。1

第一正規型: pure_の固定

まず初めに、モナド単位 pure_ について考えます。 pure_ 次の型をもっています。

pure_ :: forall a. a -> F a

このような型をもつ定義は

  •   pure_ x = ◯[x,x]
  •   pure_ x = ●[x,x]

のどちらかしかありえません。なぜならば、pure_は任意の型aについて定義されていなければならないため、 引数x :: a対してpure_の定義として可能なことは、xをそのまま戻り値に使用する以外にないためです。 さらに、

  • x 以外の a 型の値を得ることはできない
  • x の値をそのまま使う以外の方法で、xに依存して処理を変えることはできない (“パターンマッチ”ができない)

ため、“どのxに対しても◯[_,_]というコンストラクタにxを詰めて返す” あるいは “●[_,_]に詰めて返す” 以外の定義が不可能だからです。2

この2種類のpure_の両方を考えなくて済むように、pure_ x = ◯[x,x]であるインスタンスを 第一正規型のインスタンス と呼び、以後は第一正規型のインスタンスだけを考慮することにします。 これは問題なく可能であり、なぜならば前述したコンストラクタ◯と●を入れ替える同型notF によって、pure_ x = ●[x,x]であるようなインスタンスは、それと同型なpure_ x = ◯[x,x]であるようなインスタンスが存在するからです。

さて、ひとたびpure_が定まると、モナド則のうち左右の単位則から次のことがわかります。

join_ ◯[ b[x0,x1], b[x0,x1] ] = b[x0,x1]
join_ b[ ◯[y0,y0], ◯[y1,y1] ] = b[y0,y1]

となります。ここで、この2式にb = ◯とすることで

join_ ◯[ ◯[x0,x1], ◯[x0,x1] ] = ◯[x0,x1]
join_ ◯[ ◯[y0,y0], ◯[y1,y1] ] = ◯[y0,y1]

が得られ、これを同時に満たすためには

join_ ◯[ ◯[x00,x01], ◯[x10,x11] ] = ◯[x00,x11] -- (join-◯-◯)

でなければなりません。この式は今後もよく用いるので、(join-◯-◯)と名前をつけておきます。

第二正規型と第三正規型: 外側が◯のjoin_の固定

第一正規型のインスタンスにおいて、外側が◯のjoin_、すなわち

join_ ◯[ b[x0,x1], b'[x2,x3] ] = ?[?,?]

については、この時点で多くのことがわかります。 まず、join_の結果のコンストラクタ部分だけを表す関数をj :: F Bool -> Boolとおきます。

join_ (F a (F b _ _) (F b' _ _)) = F (j (F a b b')) _ _

略記法では以下のようになります。

join_ a[ b[_,_], b'[_,_] ] = (j a[b,b'] )[_,_]

ここで、モナド則のの結合法則において外側の演算がすべて◯である場合を考えます。 すなわち、モナド則から得られる

  join_ . join_      $ ◯[ ◯[ b00[_,_] , b01[_,_] ], ◯[ b10[_,_] , b11[_,_] ]]  -- (*1)
= join_ . fmap join_ $ ◯[ ◯[ b00[_,_] , b01[_,_] ], ◯[ b10[_,_] , b11[_,_] ]]  -- (*2)

という等式です。(*1)の最初のjoin_は(join-◯-◯)が適用でき、fmap join_ でjoin_を中に移動させると

  join_ ◯[ b00[_,_] , b11[_,_] ]  -- (*1')
= join_ ◯[ join_ ◯[ b00[_,_] , b01[_,_] ], join_ ◯[ b10[_,_] , b11[_,_] ]]  -- (*2)

となります。この等式のコンストラクタ部分だけをとると、

j ◯[b00,b11] = j ◯[ j ◯[b00, b01], j ◯[b10, b11] ] -- (j-◯-◯)

です。さて、モナド則の単位則から

j ◯[◯,◯] = ◯
j ◯[●,●] = ●

がわかっていますが、残りの2パターン

j ◯[●,◯] = ?
j ◯[◯,●] = ?

についてはどうでしょうか？実は、 「j ◯[●,◯]とj ◯[◯,●]のどちらか一方が●で、他方が◯である」 ことが従います。なぜならば、両方とも◯のとき、 両方とも●のときのどちらであってもモナド則に矛盾するからです。

  • 両方とも◯である場合:

    (j-◯-◯)において(b00,b01,b10,b11) = (●,◯,◯,●)を代入した

    j ◯[●, ●] = j ◯[ j ◯[●, ◯], j ◯[◯, ●] ]

    を考えると、左辺は単位則から●に等しく、一方で右辺は仮定から

    j ◯[j ◯[●,◯], j ◯[◯,●]] = j ◯[◯,◯] = ◯

    となるため矛盾。

  • 両方とも●である場合:

    (j-◯-◯)において(b00,b01,b10,b11) = (◯,●,●,◯)を代入した

    j ◯[◯,◯] = j ◯[ j ◯[◯,●], j ◯[●,◯] ]

    を考えると、左辺は単位則から◯に等しく、一方で右辺は仮定から

    j ◯[ j ◯[◯, ●], j ◯[●, ◯] ] = j ◯[●,●] = ●

    となるため矛盾。

j ◯[●,◯]とj ◯[◯,●]のどちらが●であるかは、 F上の同型によって自由に選ぶことができます。実際、あるインスタンス def = MonadInstance { pure_; join_ } においてj ◯[●,◯] = ◯, j ◯[◯,●] = ●であったとします。 ここで、コンストラクタは固定したまま、◯の要素の並びを入れ替える同型swap_◯ によってdefと同型な別のインスタンスのdef' = MonadInstance {pure_; join'_}を考えると、

join'_ = swap_◯ . join_ . fmap swap_◯ . swap_◯
join'_ ◯[ ●[x00,x01], ◯[x10,x11] ]
 = (swap_◯ . join_ . fmap swap_◯ . swap_◯) (◯[ ●[x00,x01], ◯[x10,x11] ])
 = (swap_◯ . join_ . fmap swap_◯) (◯[ ◯[x10,x11], ●[x00,x01] ])
 = (swap_◯ . join_) (◯[ swap_◯ ◯[x10,x11], swap_◯ ●[x00,x01] ])
 = (swap_◯ . join_) (◯[ ◯[x11,x10], ●[x00,x01] ])
 = swap_◯ ●[_,_]
 = ●[_,_]

となっています。 これを固定して考えるため、第二正規型のインスタンスを、 第一正規型であってかつ

j ◯[●,◯] = ●
j ◯[◯,●] = ◯

となるようなインスタンスだとしましょう。

第二正規型のインスタンスにおける、要素部分も含めたjoin_ 全体はどうなっているでしょうか？

join_ ◯[ ●[x0,x1], ◯[x2,x3] ] = ●[?,?]
join_ ◯[ ◯[x0,x1], ●[x2,x3] ] = ◯[?,?]

まず、すぐにわかるのが次の事実です。

join_ ◯[ ◯[x,x], ●[y,y] ] = ◯[x,y]

実際、

join_ ◯[ ◯[x,x], ●[y,y] ]
    -- 各要素を書き換え
  = join_ ◯[ join ◯[◯[x,x], ◯[x,x]], join ◯[●[y,y],◯[y,y]] ]
  = join_ . fmap join_ $ ◯[ ◯[◯[x,x], ◯[x,x]], ◯[●[y,y],◯[y,y]] ]
    -- モナド則
  = join_ . join_      $ ◯[ ◯[◯[x,x], ◯[x,x]], ◯[●[y,y],◯[y,y]] ]
    -- join-○-○ を2回適用
  = join_ ◯[ ◯[x,x], ◯[y,y] ]
  = ◯[x,y]

です。同じパターンにおいて変数を増やして考えると、

◯[x,y']
  = join_ ◯[ ◯[x,x], ◯[y,y'] ]
  = join_ . join_ $ ◯[ ◯[◯[x,x], ◯[x,x]], ◯[●[y,y],◯[y',y']] ]
    -- モナド則
  = join_ ◯[ join_ ◯[◯[x,x], ◯[x,x]], join_ ◯[●[y,y],◯[y',y']] ]
  = join_ ◯[ ◯[x,x], join_ ◯[●[y,y],◯[y',y']] ]

となっています。ここで、左辺にy'が現れていることから、join_ ◯[●[y,y],◯[y',y']] = ●[?,?]の右辺の 少なくとも片方にはy'が現れていなければなりません。 また、両方y'であることは否定できます。

  • 変数名を変更し、join_ ◯[●[x,x],◯[y,y]] = ●[y,y]と仮定して矛盾を導く。

    ●[y,y]
  = join_ ◯[●[x,x],◯[y,y]]
  = join_ . join_ $ ◯[ ◯[●[x,x],◯[y,y]], ◯[◯[x,x],◯[y,y]] ]
    -- モナド則から
  = join_ ◯[ join_ ◯[●[x,x],◯[y,y]], join_ ◯[◯[x,x],◯[y,y]] ]
    -- 仮定から
  = join_ ◯[ ●[y,y], ◯[x,y] ]

    より、

       join_ ◯[●[x,x],◯[y,y]]
 = join_ ◯[●[y,y],◯[x,y]]
 = ●[y,y]

    であるが、これが同時に成り立つためには

    join_ ◯[ ●[_,_], ◯[_,y] ] = ●[y,y]

    でなければならない。一方、

    ●[x,y]
 = join_ ◯[●[x,y], ●[x,y]]
 = join_ . join_ $ ◯[ ◯[●[x,y], ◯[x,y]], ◯[◯[x,y], ●[x,y]] ]
 = join_ $ ◯[ join_ ◯[●[x,y], ◯[x,y]], join_ ◯[◯[x,y], ●[x,y]] ]
 = join_ $ ◯[ ●[y,y], join_ ◯[◯[x,y], ●[x,y]] ]

    でなければならないが、join_ ◯[◯[x,y], ●[x,y]] = ◯[_,z] (z ∈ {x,y})よりこの右辺は ●[z,z]に等しく、一般のx,yに対してはz=xでもz=yでも左辺と等しくならない。

したがって、join_ ◯[●[y,y],◯[y',y']]は●[y,y']か●[y',y]のいずれかです。 ここで三度、任意の第二正規型のインスタンスは、 第三正規型 すなわち

join_ ◯[●[y,y],◯[y',y']] = ●[y,y'] -- (●-rep)

を満たすインスタンスに、適宜 ●のコンストラクタの要素を入れ替える同型swap_●を用いることで同型になります。

さて、ここまでの”同型の中から選ぶ”ことで、●と◯の入れ替え、◯の要素の順序、 ●の要素の順序が固定されました。これらを固定するF上の同型はすでに恒等写像のみになっており、 これ以上の”正規化”は存在しません。逆にいえば、 異なる第三正規型をもつインスタンスどうしを同型にするようなモナド同型は存在しないので、 第三正規型のインスタンスを全て列挙することができれば、F上のモナドのインスタンスを同型を除いて全て得られたことになります。

第三正規型の条件である(●-rep)は、(join-◯-◯)から得られるjoin_ ◯[◯[y,y],◯[y',y']] = ◯[y,y'] とそっくりな見た目をしており、これらを組み合わせると、任意のb ∈ {●,◯}について

join_ ◯[b[x,x],◯[y,y]] = b[x,y] -- (rep)

がいえます。 この(rep)は非常に便利な等式です。任意のb[_,_]を外側が◯のjoinという 単位律が使える形に書き換えてしまうからです。実際、(rep)によってすでに 外側が◯であるjoinは全パターン決定できていることがわかります。

join_ ◯[b0[x,_],b1[_,y]] = b0[x,y] -- (join-◯)

  • 証明: (rep)を使って等式変形をする。

    join_ ◯[ b0[x,_], b1[_,y] ]
  -- 内側に(rep)を適用
= join_ ◯[ join_ ◯[b0[x,x], ◯[_,_]], join_ ◯[ b1[_,_], ◯[y,y] ] ]
  -- モナド則
= join_ . join_ $ ◯[ ◯[b0[x,x], ◯[_,_]], ◯[ b1[_,_], ◯[y,y] ] ]
  -- (join-◯-◯)
= join_ $ ◯[ b0[x,x], ◯[y,y] ]
  -- (rep)
= b0[x,y]

第一から第三の正規型をまとめると、

  • 第一正規型: pure_ x = ◯[x,x]
    • pure_ x = ●[x,x] ならば、 notF によって第一正規型のインスタンスと同型
  • 第二正規型: 第一正規型かつ join_ ◯[ ●[_,_], ◯[_,_] ] = ●[_,_]
    • join_ ◯[ ●[_,_], ◯[_,_] ] = ◯[_,_] ならば、 モナド則から join_ ◯[ ◯[_,_], ●[_,_] ] = ●[_,_] でなければならず、 swap_◯によって第二正規型のインスタンスと同型
  • 第三正規型: 第二正規型かつ join_ ◯[●[y,y],◯[y',y']] = ●[y,y']
    • モナド則からこの右辺は●[y,y']と●[y',y]のどちらかに限られ、 ●[y',y]ならば swap_● によって第三正規型のインスタンスと同型

となります。

外側が●のjoin_

第三正規型のインスタンスにおいて、ここまで得た(rep)などの等式を使うと、 外側が●であるjoin_についても多くの情報が得られます。

join_ ●[b0[x,x'],b1[y,y']]
   -- (rep) を ●[b0[x,x'],b1[y,y']] に適用
 = join_ . join_ $ ◯[ ●[b0[x,x'], b0[x,x']], ◯[ b1[y,y'], b1[y,y'] ] ]
   -- モナド則
 = join_ ◯[ join_ ●[b0[x,x'], b0[x,x']], join_ ◯[ b1[y,y'], b1[y,y'] ] ]
   -- 右側の子の join_ を (join-◯) で簡約
 = join_ ◯[ join_ ●[b0[x,x'], b0[x,x']], b1[y, y'] ]
   -- (join-◯)より、外側が◯のjoinは右側の子のコンストラクタに依存しない
 = join_ ◯[ join_ ●[b0[x,x'], b0[x,x']], ◯[y, y'] ]

すなわち、外側が●であるjoinは、join_ ●[b0[x,x'], b0[x,x']] だけ決めれば決定されているということです。 そこで、次のようにおきましょう。

join_ ●[b[x,x'], b[x,x']] = c(b)[ z(b,x,x'), z'(x,x') ]
  -- (define-cz)

ただし、c,z,z'は次の型をもつ未知の関数です。

c :: Bool -> Bool
z  :: forall a. (Bool,a,a) -> a
z' :: forall a. (Bool,a,a) -> a

このとき、外側が●の任意のjoin_はc, zを用いて記述でき、特にz'は不要であることがわかります。

join_ ●[ b0[x,x'], b1[y,y'] ]
   -- 前述の変形
 = join_ ◯[ join_ ●[b0[x,x'], b1[x,x']], ◯[y, y'] ]
   -- (define-cz)
 = join_ ◯[ c(b)[ z(b,x,x'), z'(x,x') ], ◯[y, y'] ]
   -- (rep)
 = c(b)[ z(b,x,x'), y' ]

まとめると、

-- (join-●)
join_ ●[b0[x,x'],b1[y,y']] = c(b0)[ z(b0,x,x'), y' ]

となります。

更に、z(b,x,x')はbに依存しないこともいえます。 実際、

c(b0)[ z(b0,x,x'), y']
   -- (join-●)
 = join_ ●[ b0[x,x'], b1[y,y'] ]
   -- (join-◯) を内側の `b0[x,x'], b1[y,y']` に逆向きに適用
 = join_ ●[ join_ ◯[ b0[x,x], b0[x',x'] ], join_ ◯[ b1[y,y], b1[y',y'] ] ]
   -- モナド則
 = join_ . join_ $ ●[ ◯[ b0[x,x], b0[x',x'] ], ◯[ b1[y,y], b1[y',y'] ] ]
   -- (join-●)
 = join_ c(◯)[ z(◯, b0[x,x], b0[x',x']), b1[y',y'] ]
   -- (zのparametricity)
 = join_ c(◯)[ b0[z(◯,x,x'), z(◯,x,x')], b1[y',y'] ]
   -- c(◯) = j ●[◯,◯] = ●
 = join_ ●[ b0[z(◯,x,x'), z(◯,x,x')], b1[y',y'] ]
   -- (join-●)
 = c(b0)[ z(b0, z(◯,x,x'), z(◯,x,x')), y']
   -- (zのparametricity)
 = c(b0)[ z(◯,x,x'), y']

より、z(b0,x,x') = z(◯,x,x')です。ただし、(zのparametricity)と書いたステップは、 pure_が2通りしかありえないことを述べたときと同様の議論により 「z :: forall a. (Bool,a,a) -> aという型の関数zは z(b,x,x') がxの型aによらず b :: Boolの値のみに依存してxまたはx'を選択する関数である」 が成り立つという事実を用いています。

z(b,x,x') = z(x,x')と再定義して、(join-●)は 以下のように書き換えてしまいましょう。

c :: Bool -> Bool
c(b) = j ●[b,b]

z :: forall a. (a,a) -> a

join_ ●[b0[x,x'],b1[y,y']] = c(b)[z(x,x'),y']

ここで、再定義前の(zのparametricity)と同様に、z(x,x')はz(x,x')=xもしくはz(x,x')=x'のどちらかであること、 すなわちz=fstかz=sndのどちらかに限られています。

更に、外側が◯のケースと●のケースをまとめてしまいましょう。

(*) :: Bool -> Bool -> Bool
(◯ * b) = j ◯[b,b] = b
(● * b) = j ●[b,b] = c(b)

p :: forall a. (Bool,a,a) -> a
p(◯,x,x') = x
p(●,x,x') = z(x,x')

join_ a[b0[x,x'],b1[y,y']] = (a*b)[p(a,x,x'), y']

これがモナド則をすべて満たすためには、どのような制約が必要でしょうか？ 単位則はすでに満たしているので、結合則を確かめます。 まず、もっとも外側が◯である場合には、モナド則は自動的に満たされています。

(左辺)
 = join_ . join_ $ ◯[a0[b00[x0,x1], b01[x2,x3]], a1[b10[x4,x5], b11[x6,x7]] ]
  = join_ $ a0[ b00[x0,x1], b11[x6,x7] ]
  = (a0 * b00)[ p(a0,x0,x1), x7 ]
= (右辺)
 = join_ . fmap join_ $ ◯[a0[b00[x0,x1], b01[x2,x3]], a1[b10[x4,x5], b11[x6,x7]] ]
  = join_ ◯[ join_ a0[b00[x0,x1], b01[x2,x3]], join_ a1[b10[x4,x5], b11[x6,x7]] ]
  = join_ ◯[ (a0 * b00)[p(a0,x0,x1), x3], (a1 * b10)[_, x7] ]
  = (a0 * b00)[ p(a0,x0,x1), x7 ]

もっとも外側が●である場合は以下の等式となり、

(左辺)
 = join_ . join_ $ ●[　a0[b00[x0,x1], b01[x2,x3]], a1[b10[x4,x5], b11[x6,x7]] ]
   = join_ $ c(a0)[ z(b00[x0,x1], b01[x2,x3]), x7 ]
   = join_ $ c(a0)[ z(b00,b01)[z(x0,x2), z(x1,x3)], x7 ]
   = (c(a0) * z(b00,b01))[ p(c(a0),z(x0,x2),z(x1,x3)), x7 ]
= (右辺)
 = join_ . fmap join_ $ ●[　a0[b00[x0,x1], b01[x2,x3]], a1[b10[x4,x5], b11[x6,x7]] ]
   = join_ ●[ join　a0[b00[x0,x1], b01[x2,x3]], join_ a1[b10[x4,x5], b11[x6,x7]] ]
   = join_ ●[ (a0 * b00)[p(a0,x0,x1), x3], (a1 * b10)[_, x7] ]
   = c(a0 * b00)[ z(p(a0,x0,x1), x3), x7 ]

ですから、両辺の比較より

-- (eq1)
c(a0) * z(b00,b01) = c(a0 * b00)
-- (eq2)
p(c(a0),z(x0,x2),z(x1,x3)) = z(p(a0,x0,x1), x3)

を満たせば、c, zから定義されるjoinはモナド則を満たします。

c(◯) = j ●[◯,◯] = ●は既知なので、c(●)が◯と●のそれぞれの場合について検討してみましょう。

c(●) = j ●[●,●] = ◯の場合

この場合、join_には唯一の定義が定まります。(eq1)にa0 = ●を代入すると、

  (左辺) = c(●) * z(b00,b01) = ◯ * z(b00, b01) = z(b00, b01)
= (右辺) = c(● * b00) = c(c(b00)) = b00

ですが、これが恒等的に成り立つためにはz(x,x') = xすなわちp(a,x,x') = xが必要です。 このとき(eq2)も成り立っているため、c(●) = ◯, z(x,x') = xは モナド則を満たすjoin_を定めます。

これは Product (Writer Xor) Identity と同型なケースに該当し、そのことは

iso1 :: Product (Writer Xor) Identity a -> F a
iso1 (Pair (Writer (Xor b, x0)) (Identity x1)) = F b x0 x1

がモナド同型であることから確認できます。

c(●) = j●[●,●] = ●の場合

c(●)=●のとき、任意のbについてc(b) = ●です。(eq1)は

c(a0) * z(b00,b01) = ● * z(b00, b01) = ● = c(a0 * b00)

よりzと無関係に成立し、(eq2)も

  • z(x,x') = xのとき

    p(c(a0),z(x0,x2),z(x1,x3)) = p(●,x0,x1) = z(x0,x1) = x0
z(p(a0,x0,x1), x3) = p(a0,x0,x1) = x0

    より成立

  • z(x,x') = x'のとき

    p(c(a0),z(x0,x2),z(x1,x3)) = p(●,x2,x3) = z(x2,x3) = x3
z(p(a0,x0,x1), x3) = x3

    より成立

するため、c(b) = ●のとき、z(x,x') = xとz(x,x') = x' のどちらもモナド則を満たすjoin_を定めます。 第三正規型であるインスタンスどうしが同型なのはもともと等しい場合に限るのでしたから、 これらは同型ではありません。

  • z(x,x') = x の場合は Product (Writer Any) Identity と同型なケースに該当し、そのことは

    iso2 :: Product (Writer Any) Identity a -> F a
iso2 (Pair (Writer (Any b, x0)) (Identity x1)) = F b x0 x1

    がモナド同型であることから確認できます。

  • z(x,x') = x' の場合は、実は冒頭に述べた定義の3番目のケースそのものです。
